# UGS v0.3.17

**Release status:** formal release.

**Specification:** UGS v0.3 remains the active policy and conformance
profile. This release adds the first generated empty-repository bootstrap
package and its remote Release consumer verification.

## Summary

UGS now includes a baseline initializer that creates a policy, schema, managed
hooks, CR template, policy validator, and bootstrap commit in an empty Git
repository. It supports dry runs, explicit migration mode, and overwrite
protection.

The tagged source also produces a reproducible `ugs-bootstrap/v1` archive with
a source-commit-bound manifest and SHA-256 checksum. The release workflow
publishes these assets and then downloads them through the GitHub Releases API
on a clean runner to verify the package and initialize a separate repository.

The conformance and disposable Git suites continue to cover independent
fixture comparison, SSH signatures, annotated tags, hooks, integration
strategies, and protected refs. Push validation now falls back to the
protected baseline when a force-push predecessor is no longer reachable.

## Compatibility

Existing repositories are unchanged. The bootstrap package currently provides
the `baseline` profile and uses the versioned `ugs-bootstrap/v1` package
format. Existing files are preserved by explicit `--migrate`; non-empty
directories are rejected by default.

## Verification

The release tag workflow must pass `scripts/validate_release_tag.sh`,
`scripts/test_bootstrap_package.sh`, and the remote
`scripts/test_bootstrap_release.sh` consumer check. Local verification before
tagging includes `scripts/validate_repo.sh`,
`scripts/ugs_check.sh --format json`, and `git diff --check`.

Verify the release tag and assets with:

```bash
scripts/validate_release_tag.sh v0.3.17
gh release download v0.3.17 --pattern 'ugs-bootstrap-v0.3.17*'
sha256sum -c ugs-bootstrap-v0.3.17.tar.gz.sha256
```

## Rollback

Do not delete or replace the published tag or assets. If the bootstrap
consumer check fails, do not consume the release and publish a superseding
patch release after correcting the generator or release workflow.
