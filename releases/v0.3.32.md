# UGS v0.3.32

This release consolidates the UGS command reference and adds a stable help
surface to the scripts/ugs.sh wrapper.

## Summary

The release adds docs/git/ugs-cli.md as the task-oriented command reference,
links the bootstrap quick start and normative package guide to that reference,
and adds the CLI entry point to the generated document map. The wrapper now
supports top-level --help and help output while preserving the existing
command dispatch and subcommand help behavior.

The command guide documents initialization, offline migration, the upgrade
compatibility alias, explicit profile activation, branch closure, rollback,
profile validation, and the boundary between a minimal direct initialization
and a full release-package migration.

## Included scope

- add the canonical CLI usage guide to the published documentation set;
- connect README, bootstrap, and current-standard navigation to the guide;
- add stable top-level help to scripts/ugs.sh;
- add CLI help fixtures and include them in the conformance check;
- verify the new guide is present in source and published bootstrap packages; and
- publish the v0.3.32 bootstrap package and release packet.

## Compatibility

The policy schema, policy_version: 0.3, active branch model, migration report
format, and existing command semantics remain unchanged. migrate remains the
preferred offline migration command; upgrade remains a compatibility alias.
The new help output is additive.

The v0.3.32 tag target uses the documented basic supply-chain staging profile.
After the immutable tag and bootstrap digest exist, a separate signed CR will
restore the active high-trust declaration and bind the v0.3.32 evidence.

After publication, run scripts/test_bootstrap_release.sh v0.3.32, build the
package twice with SOURCE_DATE_EPOCH=0, and validate the post-tag evidence
with scripts/validate_supply_chain_release.sh v0.3.32 .ugs/policy.json
Semcosm/UGS after the high-trust evidence CR is integrated.

## Rollback

Release tags are append-only. Do not delete, replace, or force-update
v0.3.31 or v0.3.32. If the command, documentation, archive, or evidence is
defective, retain the immutable objects and publish a later signed superseding
patch through a new CR. A consumer migration can be recovered with the
external backup created by migrate, upgrade, or activate.

## Breaking Change

No. This release adds documentation, help output, and fixtures without
changing the v0.3 policy or existing migration behavior.

## Backport Target

None.
