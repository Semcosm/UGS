# UGS v0.3.30

This governance patch release closes the post-v0.3.29 audit and publishes the
repository state for the next branch-management feature.

## Summary

The release updates the v0.3 roadmap baseline to v0.3.29, records the manual
review worksheet for the post-v0.3.29 tag distribution, marks the old Phase A-F
grouping as historical planning, and publishes the v0.3.31 branch-closure
design. It also carries the release packet for the two-phase v0.3.30
supply-chain publication.

The signed v0.3.30 tag target intentionally uses supply_chain.profile: basic
and carries no active evidence paths. This staging state is required because
evidence that names the tag target commit cannot be committed into that same
commit without a hash cycle. The tag checkout is therefore not a claim that
v0.3.30 is evidence-complete high-trust.

After the immutable tag is published, a separate signed CR will build the
bootstrap archive twice with SOURCE_DATE_EPOCH=0, record the matching artifact
digest, generate the v0.3.30 SPDX SBOM and build record, create a signed
ugs-attestation, and restore main to high-trust with v0.3.30 evidence paths.

## Included scope

- update the v0.3 roadmap baseline from v0.3.28 to v0.3.29;
- mark the Phase A-F grouping from CR-0070 as a historical, non-normative
  planning draft pending manual review;
- publish the post-v0.3.29 candidate tag distribution audit;
- publish the v0.3.31 branch-closure design; and
- register the new roadmap and release documents in the generated document map.

## Compatibility

The release is documentation-only and does not change runtime commands,
consumer branch governance, or policy_version: 0.3. The temporary basic
profile applies only to the immutable v0.3.30 tag target and is explicitly
superseded by the post-tag evidence CR on main.

## Verification

Before tagging, run:

    scripts/validate_repo.sh
    scripts/ugs_check.sh --format json
    scripts/test_bootstrap_package.sh
    scripts/test_bootstrap_upgrade.sh
    scripts/test_bootstrap_equivalence.sh
    scripts/test_profile_conformance.sh
    scripts/test_conformance.sh
    scripts/test_git_fixtures.sh
    scripts/validate_document_map.py
    scripts/validate_cr_coverage.sh HEAD
    scripts/validate_commit_range.sh v0.3.29..HEAD
    scripts/validate_commit_signatures.sh v0.3.29..HEAD

After publication and the evidence CR, verify:

    scripts/validate_release_tag.sh v0.3.30
    scripts/test_bootstrap_release.sh v0.3.30
    scripts/validate_supply_chain_release.sh v0.3.30 .ugs/policy.json Semcosm/UGS

The post-tag CR must record the tag target commit, both deterministic build
runs, the final archive digest, all evidence paths, and the signed attestation
verification result.

## Rollback

Release tags are append-only. Do not delete, replace, or force-update
v0.3.29 or v0.3.30. If the staging tag, archive, or evidence is defective,
leave the immutable objects in place and publish a later signed superseding
patch through a new CR. If the post-tag policy update is rejected, revert it
through a reviewed CR while retaining the audit records and tag.

## Breaking Change

No. This release adds governance documentation and an explicitly documented,
temporary release staging step; it does not change runtime behavior or consumer
branch governance.

## Backport Target

None.
