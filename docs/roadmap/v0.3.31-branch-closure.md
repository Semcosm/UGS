# UGS v0.3.31 Branch Closure Design

**Status:** design proposal; implementation is reserved for v0.3.31

**Relationship to v0.3.30:** this document is published with the v0.3.30
planning closure, but the branch-closure command and validators are not part of
v0.3.30.

## Goal

Give a maintainer one predictable command for retiring short-lived topic
branches after integration, while preserving enough Git evidence to explain
why the branch was closed. The feature addresses branch-count growth without
turning branch cleanup into an unsafe bulk delete.

## Proposed command surface

    ugs branch close <branch> [--target main] [--remote origin]
    ugs branch close <branch> --archive --reason "<text>"
    ugs branch close <branch> --dry-run
    ugs branch close <branch> --format json

The common path is one command after a change is integrated:

1. resolve the local and tracking refs;
2. confirm the branch is not protected and is a declared topic branch;
3. confirm the target branch contains the branch tip;
4. locate the integrated CR by the branch head or commit range;
5. confirm the worktree and other worktrees do not still use the branch;
6. show the local and remote deletion plan; and
7. delete the local branch and its tracking ref after all checks pass.

--dry-run prints the same plan without changing refs. --format json returns
the branch name, target, tip OID, matched CR, local result, remote result, and
any refusal reason so CI or cleanup scripts can consume it.
The local branch is the default deletion target. Supplying --remote origin opts
into deleting the matching remote branch after the remote OID check; omitting
--remote keeps the remote branch intact.

## Abandoned work

A branch that is not merged into the target is refused by the normal close
path. The explicit --archive --reason path preserves its tip under an archive
ref such as refs/ugs/archive/<branch> before deleting the visible branch. The
archive operation records the reason and source OID in the JSON report. It
never deletes a protected ref and it never overwrites an existing archive ref.

## Safety and audit rules

- main and every ref in branching.protected_refs are never closable.
- The default close path requires a reachable integrated CR; it does not infer
  completion from a branch name or from a hosting-platform UI state.
- The command is idempotent: a branch already closed with the same source OID
  reports its prior result instead of failing on a missing local ref.
- Remote deletion is attempted only after the local preflight passes and the
  tracking ref still points at the expected OID. A changed remote ref causes a
  refusal with the observed OID.
- The command produces no release tag and does not rewrite protected history.
- A later implementation CR must add fixtures for merged branches, unmerged
  refusal, archive mode, protected-ref refusal, worktree conflicts, remote
  races, and repeated invocation.

## Implementation boundary for v0.3.31

The implementation is expected to add a branch subcommand to the existing
scripts/ugs.sh entrypoint, a small reference implementation, JSON report
schema, Bash/Python fixtures, bootstrap wiring, and documentation. The active
v0.3 policy remains unchanged until that implementation is reviewed and
integrated by a separate CR.
